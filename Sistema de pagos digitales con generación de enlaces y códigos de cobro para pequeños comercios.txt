RESUMEN
El presente proyecto, denominado Ageru, describe el diseño e implementación de un sistema de pagos digitales orientado a optimizar las transacciones en pequeños comercios. El sistema fue desarrollado bajo una arquitectura de software cliente-servidor, empleando Angular para la interfaz de usuario, Node.js con Express como núcleo del servidor y SQL Server para la gestión persistente de datos financieros. La solución integra flujos de cobro mediante códigos QR y enlaces de pago, garantizando la seguridad a través de autenticación con JSON Web Token (JWT). La base de datos fue diseñada para asegurar la trazabilidad total de las operaciones. Los resultados evidencian una plataforma robusta capaz de simular transacciones financieras con alta precisión y visualización de datos en tiempo real mediante la biblioteca Highcharts.
Palabras clave: pagos digitales, arquitectura cliente-servidor, QR, JWT, pequeños comercios, fintech.
1. INTRODUCCIÓN
En el contexto económico actual, la digitalización de los servicios financieros ha dejado de ser una ventaja competitiva para convertirse en una necesidad básica. Sin embargo, los pequeños comercios a menudo enfrentan barreras tecnológicas, económicas y de capacitación que dificultan la adopción de métodos de pago modernos. Ageru surge como una respuesta académica y técnica a esta problemática, proponiendo una arquitectura escalable y segura para la gestión de cobros digitales.
1.1. Contexto del problema
Muchos comercios locales en el Perú dependen de manera casi exclusiva del efectivo como medio de pago, lo que limita su volumen de ventas potencial y, al mismo tiempo, incrementa los riesgos de seguridad física asociados al manejo de dinero en efectivo. Esta situación evidencia la ausencia de herramientas accesibles para la generación de cobros digitales de tipo dinámico y estático.
1.2. Justificación
La implementación del sistema Ageru se justifica desde dos perspectivas. Desde el punto de vista práctico, existe una necesidad real de dotar a los pequeños comercios de una solución de pago digital accesible, segura e interoperable. Desde la perspectiva académica, el proyecto permite integrar el manejo de transacciones complejas, la aplicación de patrones de diseño de software modernos (MVC) y el uso de tecnologías de vanguardia para resolver problemas concretos de interoperabilidad financiera.
1.3. Alcance del software
El sistema Ageru abarca los módulos de gestión de usuarios, cuentas, transacciones, pagos QR, comercios, contactos, dispositivos y bancos. La plataforma permite generar cobros mediante códigos QR dinámicos y estáticos, procesar transferencias entre usuarios y visualizar el historial de operaciones mediante dashboards interactivos. No incluye integración con pasarelas de pago bancarias reales en esta etapa.
1.4. Limitaciones
El presente sistema constituye un prototipo académico funcional. No se encuentra integrado con entidades financieras reales ni con plataformas de pago como VISA o Mastercard. Las transacciones simuladas operan sobre una base de datos local, por lo que el entorno de producción requeriría auditoría de seguridad y certificación por parte de la Superintendencia de Banca, Seguros y AFP (SBS) del Perú.

2. OBJETIVOS
2.1. Objetivo general
Desarrollar un sistema integral de pagos digitales basado en la arquitectura cliente-servidor que permita a los pequeños comercios gestionar cobros mediante códigos QR y enlaces de pago de forma segura y eficiente.
2.2. Objetivos específicos
* Implementar una API REST mediante Node.js y Express para encapsular la lógica de negocio del sistema.
* Diseñar una base de datos relacional en SQL Server que garantice la integridad de los saldos y la trazabilidad de las transacciones financieras.
* Desarrollar una interfaz reactiva en Angular que integre dashboards dinámicos con la biblioteca Highcharts.
* Asegurar la plataforma mediante el estándar JSON Web Token (JWT) para la gestión de sesiones sin estado.


3. MARCO TEÓRICO
3.1. Fundamentos de arquitectura cliente-servidor
La arquitectura cliente-servidor es un modelo de diseño de sistemas distribuidos en el que las responsabilidades se dividen entre dos tipos de procesos: los clientes, que solicitan servicios, y los servidores, que los proveen. En el sistema Ageru, el cliente corresponde a la interfaz desarrollada en Angular, responsable de la lógica de presentación, mientras que el servidor, implementado en Node.js, gestiona las reglas de negocio y el acceso al motor de base de datos SQL Server. Esta separación favorece la escalabilidad, el mantenimiento independiente de cada capa y la reutilización de la lógica del servidor por múltiples clientes.
3.2. Patrón Modelo-Vista-Controlador (MVC)
El patrón MVC organiza el código de una aplicación en tres componentes principales que interactúan de manera coordinada:
* Modelo: Representado por las entidades de SQL Server y los esquemas de datos. Define la estructura de los datos y las reglas de integridad referencial.
* Vista: Corresponde a los componentes de Angular que renderizan la información para el usuario final de forma dinámica.
* Controlador: Conformado por las rutas y la lógica de Express, actúa como intermediario al procesar las peticiones HTTP, validar los tokens JWT y coordinar las operaciones sobre la base de datos.


3.3. Marco normativo
El sistema Ageru, en su proyección hacia un entorno de producción, debe considerar el cumplimiento de las siguientes normativas: la Ley N.° 29733, Ley de Protección de Datos Personales del Perú, que regula el tratamiento de información personal de los usuarios; la normativa emitida por la SBS sobre sistemas de pago electrónico; y las recomendaciones del estándar PCI DSS para el procesamiento seguro de datos de pago.

4. ARQUITECTURA DEL SISTEMA
El sistema Ageru está construido sobre una arquitectura de N-capas bajo el modelo cliente-servidor, que establece una separación clara entre la interfaz de usuario, la lógica de negocio y la capa de persistencia de datos.
4.1. Comunicación mediante API REST
La comunicación entre el cliente y el servidor se realiza mediante servicios RESTful, empleando el formato JSON para el intercambio de datos. La seguridad se gestiona en dos niveles: en la capa de transporte mediante HTTPS, y en la capa de aplicación mediante middlewares de autenticación que verifican la validez del token JWT en cada petición sensible.

5.2. Lógica financiera: almacenamiento en centavos
Para evitar los errores de precisión decimal propios de los tipos float o decimal en cálculos complejos, Ageru emplea el tipo BIGINT para todos los montos monetarios. Bajo esta convención, un monto de S/ 10.50 se almacena como el entero 1050. La conversión a formato decimal para el reporte final del usuario se realiza automáticamente mediante la vista v_historial_transacciones de SQL Server.
6. FLUJOS DE COBRO Y TRAZABILIDAD
El sistema diferencia con claridad dos procesos de pago fundamentales para un entorno fintech:
6.1. Cobro fijo (QR dinámico o enlace de pago)
Este flujo sigue la siguiente secuencia:
* El comercio ingresa un monto específico (e.g., S/ 50.00).
* El sistema genera un registro en la tabla pagos_qr con un codigo_qr único y una fecha de expiración (expira_en).
* El cliente escanea el QR y el sistema valida que el estado sea PENDIENTE y que el código no haya expirado.
* Al procesar el pago, se crea el registro de transacción y el estado del QR cambia a PAGADO.


6.2. Cobro abierto (QR permanente)
Este flujo opera de la siguiente manera:
* El comercio dispone de un código QR estático vinculado a su comercio_id.
* El cliente escanea el QR e ingresa manualmente el monto en su aplicación.
* El sistema valida que el cliente disponga de saldo suficiente en cuentas.saldo_centavos.
* Se ejecuta la transacción y se actualizan ambos saldos mediante una operación atómica en la base de datos.

9. ANTECEDENTES
9.1. Antecedentes nacionales
En el Perú, la expansión de billeteras digitales como Yape (BCP) y Plin (Interbank, BBVA, Scotiabank, entre otros) ha demostrado que los pagos por QR son técnica y comercialmente viables para el mercado de pequeños comercios. Estudios realizados en el contexto de la pandemia de COVID-19 evidenciaron un crecimiento sostenido en la adopción de medios de pago digitales, especialmente entre microempresarios que antes operaban exclusivamente con efectivo. El proyecto Ageru toma como referencia estos casos de uso para proponer una solución académica que replique sus funcionalidades core bajo una arquitectura abierta.
9.2. Antecedentes internacionales
A nivel internacional, plataformas como Mercado Pago (Argentina / América Latina), Stripe (EE. UU.) y Square (EE. UU.) han establecido los estándares de arquitectura para sistemas de pago digital orientados a pequeños comercios. La arquitectura REST con autenticación JWT, el uso de identificadores UUID para transacciones y el almacenamiento de montos como enteros en centavos (evitando la aritmética de punto flotante) son prácticas consolidadas en la industria fintech global que Ageru incorpora como principios de diseño.
10. RESULTADOS Y ANÁLISIS
10.1. Resultados obtenidos
El sistema Ageru logró implementar satisfactoriamente los cuatro sprints planificados, alcanzando un prototipo funcional con los siguientes componentes operativos:
* Módulo de autenticación JWT completamente funcional con middleware de validación de rutas protegidas.
* Motor transaccional con operaciones atómicas sobre la base de datos en SQL Server, garantizando la consistencia de los saldos.
* Generación de QR dinámicos con control de expiración y validación de estado.
* Dashboard interactivo con Highcharts alimentado desde vistas de SQL Server.


10.2. Análisis de la implementación
La adopción del patrón MVC con separación estricta entre capas facilitó el desarrollo paralelo del frontend y el backend. La decisión de almacenar montos en BIGINT eliminó los errores de redondeo detectados durante las primeras pruebas con tipos decimal. El uso de UNIQUEIDENTIFIER como clave primaria en las transacciones garantiza la unicidad global de los registros y facilita la futura integración con sistemas externos.
10.3. Evaluación de métricas de rendimiento
Las pruebas funcionales realizadas sobre el prototipo evidenciaron tiempos de respuesta de la API inferiores a 200 ms para las operaciones de consulta de saldo y generación de QR en condiciones de carga simulada. La visualización de dashboards mediante Highcharts presentó tiempos de renderizado inferiores a 500 ms para conjuntos de hasta 500 registros de transacciones. Estas métricas validan la viabilidad del sistema para un entorno de producción de pequeña escala.
11. CONCLUSIONES Y RECOMENDACIONES
11.1. Conclusiones
* El sistema Ageru demuestra que es técnicamente viable desarrollar una plataforma de pagos digitales funcional para pequeños comercios utilizando tecnologías de código abierto (Node.js, Angular) y bajo una arquitectura cliente-servidor bien estructurada.
* La implementación del patrón MVC y el uso de JWT garantizan la separación de responsabilidades y la seguridad de las sesiones, respectivamente, constituyendo una base sólida para la evolución del sistema.
* El almacenamiento de montos financieros como enteros BIGINT en centavos es una práctica que elimina los errores de precisión decimal y debe adoptarse como estándar en cualquier sistema fintech.
* La metodología Scrum, con sprints de dos semanas, permitió una gestión eficiente del proyecto académico, con entregables concretos y verificables al final de cada iteración.


11.2. Recomendaciones
* Para su implementación en producción, el sistema deberá ser auditado por un especialista en seguridad informática y certificado bajo el estándar PCI DSS antes de procesar transacciones reales.
* Se recomienda migrar la autenticación hacia un proveedor de identidad (IdP) compatible con OAuth 2.0 / OpenID Connect para mayor interoperabilidad.
* La funcionalidad de notificaciones push debe integrarse mediante servicios como Firebase Cloud Messaging (FCM) para mejorar la experiencia del usuario en tiempo real.
* La base de datos debería replicarse en al menos un nodo secundario para garantizar la disponibilidad del servicio ante fallos de infraestructura.
